# Генератор отчетов по практике

Помощник для Codex: изучает ваш программный проект, готовит отчет DOCX по примеру и проверяет оформление. Все накопленные правила отступов, интервалов, содержания, рисунков, таблиц и выводов сохранены для всех пользователей. Официальные требования общие; структура и сведения о проекте берутся из ваших материалов.

## Как начать

1. Откройте папку генератора в Codex как проект. Для новой работы используйте чистую копию генератора.
2. Положите исходники своего приложения в `project/`, например `project/my-app/`. Добавьте README с запуском и индивидуальное задание: файл или его текст.
3. В `references/current-example/` положите актуальный пример отчета, желательно DOCX. В `references/previous-reports/` — прошлые отчеты для стиля. Названия файлов любые. Если примеров несколько, укажите основной. `references/official/` оставьте без изменений.
4. Заполните `config/student.yaml` или оставьте пустые поля: Codex спросит данные и заполнит их. Нужны ФИО, группа, специальность, учреждение, сведения о практике, руководители и тема проекта. Руководителей из примера нужно подтвердить.
5. Отправьте промпт ниже и ответьте на вопросы. Готовый файл появится в `output/report.docx`.

```text
Подготовь отчет по моему проекту. Начни с AGENTS.md и
skills/generate-practice-report/SKILL.md. Сначала изучи вложенные
материалы, задай недостающие вопросы и заполни config/student.yaml.
Бери требования из references/official, структуру и титул из
references/current-example, стиль из references/previous-reports.
Сохрани все правила docs/report-spec.md и docs/writing-style.md.
Исследуй проект, попытайся собрать и запустить его; не выдумывай
функции, снимки и успешные тесты. Создай DOCX, проверь структуру,
отрендери и осмотри каждую страницу. Итог положи в output/report.docx.
```

## Что требуется на компьютере

Codex с доступом к файлам и терминалу; зависимости приложения устанавливаются по его README. Для документов нужны Python 3.10+ и библиотеки из `requirements.txt`. Codex может использовать встроенный Python через workspace dependencies. Для экспорта и обновления содержания нужен Microsoft Word на Windows либо доступный LibreOffice. Генератор проверяет доступность среды и сообщает ограничения; установка Word не выполняется автоматически.

Если используете собственный Python: `python -m pip install -r requirements.txt`. Предварительная проверка: `python tools/prepare_report.py --json temp/setup.json`. Незаполненная конфигурация ожидаемо требует ответов пользователя.

## Результат и повторная работа

`output/` содержит итоговые файлы; `temp/` — черновики, журналы, извлечения и рендеры; `screenshots/` — реальные снимки и их manifest. Если снимки получить не удалось, отчет содержит подписанные пустые области, а Codex перечисляет, что вставить вручную. Перед сдачей вставьте снимки и попросите повторно проверить весь документ. Без рендера и просмотра всех страниц отчет нельзя считать полностью проверенным.

Чтобы исправить свой DOCX, положите последнюю версию в `output/report.docx` и укажите нужные правки и части, которые нельзя менять. Codex сохранит исходную копию в `temp/`. Для следующей работы возьмите чистую копию: чужие снимки, журналы и извлечения нельзя использовать как доказательства.

## Как поделиться

`python tools/package_generator.py --output output/generator.zip` собирает чистый архив: правила, инструменты, Skills, официальный PDF, пустая конфигурация и папки для входов. Ваш проект, ФИО, отчеты, примеры, снимки и temp туда не включаются. Передавайте этот архив одногруппникам.

Технические инструкции для Codex находятся в `docs/setup.md`, `docs/content-format.md` и `skills/`. Пользователю не нужно самостоятельно создавать JSON-план или писать Python-скрипты.
